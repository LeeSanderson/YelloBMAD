Key screen — Project Board

The primary working surface: a Board is a view of the Project “Website Rebuild” in the Space “Northwind Redesign”, with columns by Status. Rendered with the corrected border-hairline #6478A8, so this shows how much more gridded the accessibility fix actually made direction 4. The Role chip now carries a border too — without it the chip fill sat at 1.05:1 against the bar and read as loose text.

1 · At rest, acting as Admin

Column counts are the true total, not the loaded count — at FR-28 scale the two differ, and a count that tracks virtualisation is a lie. One card is shown focused, which is the keyboard path NFR-9 mandates.

2 · The canonical Move control

Opened from the Task’s context menu — by pointer, by Enter on a focused Task, or by the context-menu key. This is the conformance path, not a fallback. A drag is path-based, so WCAG 2.5.1 (Level A) requires a single-pointer alternative; between 768–1279px on a touch tablet there is no keyboard and no pager, so drag was previously the only route. It also works in NVDA and JAWS browse mode, where the arrow-key grammar cannot reach.

3 · Mid-drag, and the same Board as a Viewer

Left: a lifted Task with its drop zone — the only place in the design where an object leaves the plane, using a hard offset rather than a blur, because a blurred shadow does not read on a tinted ground. Right: identical data, acting as a Viewer. Every create and edit affordance is absent, not dimmed — no + on any column, no Move control, no drag. UJ-4 requires Ravi to know his standing without attempting an action.
