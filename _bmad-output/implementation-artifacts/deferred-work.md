- **`<html lang="en">` is hard-coded, so `base.css`'s 26-locale casing exclusion list is inert** — `Yello.Client/wwwroot/index.html:2`. Severity: medium. - **`opacity` or an alpha channel on a surface carrying a gated pair would make all 36 computed ratios fiction** — `tests/Yello.Tests.Architecture/ColorTokenContrastTests.cs:247-301`, `WcagContrast.cs`. - **Review archaeology is accumulating in the production files** — `Yello.Client/App.razor`, `Yello.Client/wwwroot/css/base.css`, `Yello.Client/wwwroot/css/tokens.css`. Severity: low, and it is a **project-wide convention decision rather than a defect**. The alternative is that a superseded decision lives in the commit message and the story's Change Log, and the source comment states only what is true now. Recorded rather than acted on because changing it means deleting review history that two passes deliberately preserved, and that is a call about how this project keeps its records.

- **`em`-relative lengths cannot be measured by a static parser** — `tests/Yello.Tests.Architecture/CssCorpus.cs:305-316`. Severity: medium. Owner: **the first story with a rendered surface**, alongside AC13's measurement half — same blocker B5, same browser binding. `AbsoluteLengthsPx` converts `em` at `RootFontSizePx = 16`, but `em` resolves against the *element's* font size, not the root's. Two consequences, in both directions: `min-height: 1.6em` on 13px metadata type is 20.8px and passes the 24px target floor, and `border-inline-start: 0.09em` on 20px type is 1.8px and fails the 1.5px hairline floor although it clears it. Reporting `em` as unverifiable rather than converting it makes the gate honest, which is the interim patch; knowing the real computed value needs the cascade, which means a browser.

- **AC7's device-pixel snapping half is not implemented, and needs UX to specify it** — `Yello.Client/wwwroot/css/tokens.css`, story 1.2 AC7, `DESIGN.md:366`, UX-DR4. Severity: medium. Owner: **UX, before the first story that renders a structural border** (epic 2). **Deferred by Lee's decision on 2026-08-28, reversing the first pass's decision to implement it.** `DESIGN.md:366` requires structural borders "snapped to device pixels where the platform allows" in the same sentence as the 1.5px floor. The floor is implemented and gated; the snapping is not, and is now recorded rather than derived.

  The first pass implemented it as six `resolution` bands rebinding `--border-hairline-width` to `ceil(1.5 × dppx) ÷ dppx`. That is reverted, for three reasons found at the second pass. **One:** the table had no upstream authority — no PRD requirement, epic, architecture decision or UX spine names a display-scale matrix, so the six scales and their values were invented by a code review. **Two:** it collapsed the design's two-tier border vocabulary. At 1dppx and 1.5dppx the round-up rule gives 2px, which is exactly `--border-emphasis-width` — the weight `DESIGN.md:367` reserves for the lifted card under drag — and the same pass had repointed the focus ring at that token, so ordinary hairline, lifted-card emphasis and focus ring were all 2px at the commonest desktop scale. **Three:** at 1dppx a 1px border is exactly one device pixel and does not antialias at all, so `DESIGN.md:365`'s stated reason for exceeding 1px does not apply there, yet the table raised the structural border 33% above the canonical figure at that scale.

  Two things for whoever picks this up. The bands were keyed on their lower bound only, which is not sufficient even in principle: the `2dppx…2.99dppx` band serves 2.5 and 2.625dppx displays (Windows 250%, several common Android devices) where 1.5px renders at 3.75 and 3.94 device pixels, and an open-ended `3dppx` band serves 4dppx retina at 6.67 — all antialiasing exactly as the unsnapped width does. So a correct implementation needs either a band per real device scale, from a real device matrix, or a rendered measurement in a browser (blocker B5, the same binding AC13's measurement half waits on). And the gate written for it asserted only that *some* band existed, never which — deleting the three scales AC7 names left the suite green, which is why the whole thing is reverted rather than repaired.
