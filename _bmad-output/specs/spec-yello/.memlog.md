- (constraint) Authorisation is a function of (Account, Space) and never of Account alone; the active Space is resolved before any authorisation decision is possible. Rules out a uniform tenant-column filter and forbids any requirement phrased as an Admin can X without naming the Space.
- (constraint) Isolation has no acceptable failure rate: a single verified cross-Space disclosure blocks release. Rules out shipping with a known leak and makes the isolation suite a release gate rather than a report.
- (constraint) Membership is the only route into a Space. Rules out share links, public Boards, read-only URLs and anonymous access.
- (constraint) A Project never moves between Spaces and a Task never leaves its Space. Closes the cross-Space leak by construction rather than by validation.
- (constraint) Removing a Status at either level requires mapping every occupying Task in the same atomic operation. Removal is always a migration, which makes the state of a Task holding a Status its Project does not expose unreachable rather than merely invalid.
- (constraint) A Project Status delta references Statuses by identity, not by name. Forced by the FR-27 rename cascade, which must detect that a Project renamed the same Status object.
- (constraint) An API Token is bound to exactly one Space at issue and its capability resolves at request time, not issue time. Rules out Account-scoped Tokens and a Token outliving the permission that justified it.
- (constraint) The synchronisation channel carries no authority and cannot authorise once at connection time. Every inbound frame is authorised, because FR-34 places a permission change inside a pipeline that is by design tolerant of delay and reordering.
- (constraint) Whole-field last-writer-wins is not an admissible merge for a Task description: FR-31 requires two Users editing the same region to arrive at identical persisted text with no merge prompt. Adopting it would amend CAP-31 and CAP-33 rather than being an implementation choice.
- (constraint) Deletion of an Account, Space, Project or Task is irreversible in v1. No trash, no restore, no undo on the most destructive operation in the product.
- (constraint) Total running cost stays under 30 pounds per month at the NFR-8 scale envelope. Rules out always-on dedicated infrastructure per Space or per editing session, which is the likeliest cost pressure from the real-time requirements.
- (constraint) An Account existence is never disclosed to anyone not given it: registration, authentication and invitation-issue responses are uniform whether or not the address is known. Nobody can enumerate the Spaces another Account belongs to, including a Space Owner.
- (constraint) Capabilities the acting Role lacks are absent from the interface rather than present-and-failing, and the acting Role is legible at all times. Separately, the interface hiding an action is never the enforcement mechanism: every refusal is enforced server-side and identically on the API.
